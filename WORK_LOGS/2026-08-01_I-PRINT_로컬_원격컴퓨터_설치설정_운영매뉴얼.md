## 1. 이 문서의 목적

이 문서는 새로운 로컬 컴퓨터 또는 외부 원격 컴퓨터를 I-PRINT 관제 화면에 연결하기 위한 전체 작업 절차를 정리한 문서입니다.

작업자는 이 문서만 보고 다음 작업을 진행할 수 있어야 합니다.

1. 대상 컴퓨터 사전 점검
2. 관리자 권한 SSH 접속
3. Tailscale 설치와 연결
4. I-PRINT Windows 에이전트 설치
5. Windows 방화벽 설정
6. 부팅 시 자동 실행 등록
7. 에이전트 상태 확인
8. Dell I-PRINT 서버에 신규 컴퓨터 등록
9. 외부 HTTPS 화면 검증
10. 재부팅 후 최종 검증

## 4. 작업 전 안전 원칙

1. 대상 컴퓨터의 기존 프린터 드라이버를 삭제하지 않습니다.
2. Print Spooler 설정을 임의로 변경하지 않습니다.
3. 기존 인쇄 대기열을 설치 과정에서 삭제하지 않습니다.
4. 인터넷 공유기에 8898 포트를 개방하지 않습니다.
5. SSH 22번 포트도 가능한 한 인터넷 전체에 공개하지 않습니다.
6. 에이전트 통신은 Tailscale 사설망을 우선 사용합니다.
7. Tailscale 인증 키를 문서·Git·에이전트 파일에 저장하지 않습니다.
8. 신규 장비 추가 전 `/home/bourne/I-print/00_READ_FIRST.md`를 먼저 읽습니다.
9. 서버 소스 수정 전 타임머신 백업 또는 별도 백업을 생성합니다.
10. 수정 후 로컬 상태·외부 HTTPS·Git 상태를 모두 확인합니다.

## 5. 권장 표준 설치 경로

5800X 시험 장비는 현재 아래 경로를 사용합니다.

```text
F:\iPrintAgent\printer-agent.ps1
F:\LibreHardwareMonitor\LibreHardwareMonitorLib.dll
```

그러나 여러 컴퓨터에 배포할 때는 F 드라이브가 없을 수 있으므로 이 경로를 그대로 사용하면 안 됩니다.

신규 Windows 컴퓨터는 아래 표준 경로를 사용합니다.

```text
C:\ProgramData\IPrintAgent
```

권장 파일 구조:

```text
C:\ProgramData\IPrintAgent\printer-agent.ps1
C:\ProgramData\IPrintAgent\LibreHardwareMonitorLib.dll
C:\ProgramData\IPrintAgent\install-iprint.ps1
C:\ProgramData\IPrintAgent\install.log
```

신규 배포용 `printer-agent.ps1`은 LibreHardwareMonitor DLL을 고정된 F 드라이브가 아니라 자신의 설치 폴더에서 읽도록 구성해야 합니다.

권장 PowerShell 경로 처리 예시:

```powershell
$AgentRoot = Split-Path -Parent $MyInvocation.MyCommand.Path
$HardwareDll = Join-Path $AgentRoot 'LibreHardwareMonitorLib.dll'
Add-Type -Path $HardwareDll
```

현재 5800X 원본 에이전트를 그대로 복사할 경우 아래 고정 경로를 반드시 먼저 점검합니다.

```powershell
Add-Type -Path 'F:\LibreHardwareMonitor\LibreHardwareMonitorLib.dll'
```

이 경로가 남아 있으면 F 드라이브가 없는 컴퓨터에서 CPU 온도 수집이 실패합니다.

## 6. 로컬 컴퓨터 설치 절차

로컬에서 컴퓨터 앞에 직접 앉아 작업할 때의 순서입니다.

### 6-1. 관리자 PowerShell 실행

시작 메뉴에서 PowerShell을 검색한 뒤 관리자 권한으로 실행합니다.

관리자 권한 확인:

```powershell
whoami
net session
```

`net session` 명령이 접근 거부 없이 실행되어야 합니다.

### 6-2. 컴퓨터 기본 정보 확인

```powershell
hostname
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsArchitecture
Get-Service Spooler
Get-Printer
```

확인할 항목:

```text
컴퓨터 이름
Windows 버전
64비트 여부
Print Spooler 실행 상태
설치된 프린터 수
실제 프린터 이름
```

### 6-3. Tailscale 설치

Tailscale이 이미 설치되어 있는지 확인합니다.

```powershell
Test-Path 'C:\Program Files\Tailscale\tailscale.exe'
```

설치되어 있지 않으면 공식 Windows 설치 패키지를 설치합니다.

설치 후 서비스 확인:

```powershell
Get-Service Tailscale
```

### 6-4. Tailscale 연결

일반 로그인 방식:

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' up --unattended=true
```

대량 설치용 인증 키 방식:

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' up --auth-key=일회성_인증키 --unattended=true
```

보안 주의:

```text
인증 키는 짧은 유효기간 사용
가능하면 일회성 키 사용
명령 기록과 문서에 키를 남기지 않음
Git에 키를 저장하지 않음
설치 완료 후 키가 포함된 임시 파일 제거
```

Tailscale 연결 확인:

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' status
& 'C:\Program Files\Tailscale\tailscale.exe' ip -4
```

출력된 `100.x.x.x` 주소를 작업일지에 기록합니다.

### 6-5. 에이전트 폴더 생성

```powershell
New-Item -ItemType Directory -Path 'C:\ProgramData\IPrintAgent' -Force
```

### 6-6. 에이전트 파일 배치

아래 파일을 복사합니다.

```text
printer-agent.ps1
LibreHardwareMonitorLib.dll
```

복사 후 확인:

```powershell
Get-ChildItem 'C:\ProgramData\IPrintAgent'
```

### 6-7. Windows 방화벽 설정

인터넷 전체가 아니라 Tailscale 대역에서 8898 포트로 접근하도록 제한하는 것이 원칙입니다.

기본 규칙 예시:

```powershell
New-NetFirewallRule `
  -DisplayName 'I-PRINT Agent 8898 Tailscale' `
  -Direction Inbound `
  -Action Allow `
  -Protocol TCP `
  -LocalPort 8898 `
  -RemoteAddress 100.64.0.0/10 `
  -Profile Any
```

기존 규칙 확인:

```powershell
Get-NetFirewallRule -DisplayName 'I-PRINT Agent 8898 Tailscale'
```

8898 포트를 공유기에서 포트포워딩하지 않습니다.

### 6-8. 에이전트 수동 시험 실행

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\ProgramData\IPrintAgent\printer-agent.ps1'
```

에이전트는 계속 실행되는 서버 형태이므로 별도 PowerShell 창에서 시험하거나 작업 스케줄러 등록 후 실행합니다.

로컬 상태 확인:

```powershell

```

정상 응답에 포함되어야 할 주요 항목:

```text
cpu_percent
cpu_name
temperature_c
memory_percent
disk_percent
printer_count
printer_name
spooler
printing
queued
error
updated_at
```

### 6-9. 부팅 자동 실행 등록

작업 스케줄러 이름은 컴퓨터마다 동일하게 아래 이름을 사용합니다.

```text
iPrintAgent
```

등록 예시:

```powershell
$Action = New-ScheduledTaskAction `
  -Execute 'powershell.exe' `
  -Argument "-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File C:\ProgramData\IPrintAgent\printer-agent.ps1"

$Trigger = New-ScheduledTaskTrigger -AtStartup

$Principal = New-ScheduledTaskPrincipal `
  -UserId 'SYSTEM' `
  -LogonType ServiceAccount `
  -RunLevel Highest

Register-ScheduledTask `
  -TaskName 'iPrintAgent' `
  -Action $Action `
  -Trigger $Trigger `
  -Principal $Principal `
  -Description 'I-PRINT computer and printer status agent'
```

작업 시작:

```powershell
Start-ScheduledTask -TaskName 'iPrintAgent'
```

상태 확인:

```powershell
Get-ScheduledTask -TaskName 'iPrintAgent'
Get-ScheduledTaskInfo -TaskName 'iPrintAgent'
```

정상 기준:

```text
TaskName: iPrintAgent
State: Running
Trigger: BootTrigger
RunAs: SYSTEM
RunLevel: Highest
```

## 7. 원격 SSH 설치 절차

SSH가 열려 있고 관리자 권한으로 접속 가능한 컴퓨터는 현장 방문 없이 설치할 수 있습니다.

### 7-1. SSH 접속

작업자 컴퓨터에서 실행:

```bash
ssh 관리자계정@대상컴퓨터주소
```

포트가 22번이 아닌 경우:

```bash
ssh -p 포트번호 관리자계정@대상컴퓨터주소
```

접속 후 Windows PowerShell인지 확인합니다.

```powershell
hostname
whoami
$PSVersionTable.PSVersion
```

### 7-2. 관리자 권한 확인

```powershell
net session
```

접근 거부가 나오면 현재 SSH 세션은 설치에 필요한 관리자 권한이 아닐 수 있습니다.

이 경우 관리자 그룹 포함 여부와 SSH 서비스 실행 계정을 확인해야 합니다.

### 7-3. 파일 전송

작업자 컴퓨터에서 SCP 사용 예시:

```bash
scp printer-agent.ps1 관리자계정@대상주소:'C:/ProgramData/IPrintAgent/printer-agent.ps1'
scp LibreHardwareMonitorLib.dll 관리자계정@대상주소:'C:/ProgramData/IPrintAgent/LibreHardwareMonitorLib.dll'
```

폴더가 없으면 SSH 접속 후 먼저 생성합니다.

```powershell
New-Item -ItemType Directory -Path 'C:\ProgramData\IPrintAgent' -Force
```

### 7-4. 원격 설치 실행

SSH 세션에서 다음 순서로 실행합니다.

```powershell
Get-Service Tailscale
& 'C:\Program Files\Tailscale\tailscale.exe' status
& 'C:\Program Files\Tailscale\tailscale.exe' ip -4
Get-ChildItem 'C:\ProgramData\IPrintAgent'
```

이후 방화벽 규칙과 작업 스케줄러를 6장의 절차대로 등록합니다.

### 7-5. 원격 상태 검증

대상 컴퓨터 내부 확인:

```powershell
Invoke-RestMethod http://127.0.0.1:8898/status
```

Dell 서버 또는 같은 Tailscale 네트워크의 다른 장비에서 확인:

```bash
curl -fsS http://대상_Tailscale_IP:8898/status
```

두 테스트가 모두 성공해야 합니다.

로컬 테스트만 성공하고 Dell 서버 테스트가 실패하면 아래를 확인합니다.

```text
Tailscale 연결 상태
Tailscale IP 오기록
Windows 방화벽 규칙
에이전트가 0.0.0.0 또는 http://+:8898/에서 수신하는지
Tailscale ACL
8898 포트 충돌
```

## 8. Dell I-PRINT 서버 신규 컴퓨터 등록

이 단계가 빠지면 원격 컴퓨터의 에이전트가 정상이어도 대시보드에는 나타나지 않습니다.

### 8-1. 서버 접속과 기준 문서 확인

```bash
cd /home/bourne/I-print
cat 00_READ_FIRST.md
```

최신 업무일지 확인:

```bash
find WORK_LOGS -maxdepth 1 -type f -name '*.md' -printf '%T@ %TY-%Tm-%Td %TH:%TM:%TS %f\n' 2>/dev/null | sort -nr | head -n 5
```

Git 상태 확인:

```bash
git status --short
git branch --show-current
git log -1 --oneline
```

미추적 파일이나 기존 수정사항이 있으면 신규 작업과 섞지 않습니다.

### 8-2. 현재 등록 방식 확인

현재 `app.py`에는 아래처럼 장비 주소가 직접 정의되어 있습니다.

```python
PC_5800X_AGENT_URL = "http://100.117.206.9:8898/status"
MAC_MINI_AGENT_URL = "http://100.116.128.62:8898/status"
```

신규 장비를 추가할 때 필요한 작업:

```text
신규 장비용 AGENT_URL 추가
신규 장비용 상태 API 추가
오프라인 fallback 데이터 추가
PC 화면 카드 또는 행 추가
모바일 화면 카드 또는 행 추가
JavaScript 갱신 함수 연결
표시 이름과 실제 computer_name 구분
5초 갱신 동작 확인
```

주의:

기존 코드를 전체 덮어쓰지 않습니다.

신규 상수·함수·카드 블록만 최소 단위로 추가합니다.

장비가 많아질 경우 다음 단계에서는 하드코딩 대신 `devices` 테이블 또는 `devices.json` 기반 등록 구조로 전환하는 것이 필요합니다.

### 8-3. 신규 장비 상태 API 예시

예시 장비 정보:

```text
장비 키: school01
표시명: 학생회관 01
Tailscale IP: 100.100.100.10
```

서버 내부 에이전트 주소:

```text
http://100.100.100.10:8898/status
```

상태 API 예시:

```text
/api/devices/school01/status
```

장비 키는 영문 소문자·숫자·하이픈 형태로 일정하게 관리하는 것이 좋습니다.

### 8-4. 서버에서 원격 에이전트 직접 확인

```bash
curl -fsS http://신규_Tailscale_IP:8898/status
```

정상 JSON이 출력되지 않으면 UI 수정 전에 네트워크·에이전트 문제부터 해결합니다.

### 8-5. 코드 검증

Python 문법 확인:

```bash
python3 -m py_compile app.py
```

JavaScript가 변경된 경우 브라우저 콘솔 오류도 확인합니다.

Git diff 확인:


## 11. 장애별 점검 순서

### 11-1. I-PRINT 화면에서 컴퓨터가 Offline

점검 순서:

```text
1. 대상 컴퓨터 전원
2. 인터넷 연결
3. Tailscale 서비스
4. Tailscale IP
5. iPrintAgent 작업 스케줄러
6. 127.0.0.1:8898/status
7. Dell 서버에서 Tailscale IP:8898/status
8. 서버 app.py 등록 주소
9. I-PRINT 서비스 상태
10. 브라우저 캐시와 콘솔 오류
```

### 11-2. Tailscale은 Online인데 에이전트 접근 실패

```powershell
Get-ScheduledTask -TaskName 'iPrintAgent'
Get-NetTCPConnection -LocalPort 8898
Get-NetFirewallRule -DisplayName 'I-PRINT Agent 8898 Tailscale'
Invoke-RestMethod http://127.0.0.1:8898/status
```

가능한 원인:

```text
에이전트 미실행
PowerShell 파일 경로 오류
작업 스케줄러 실행 인자 오류
8898 포트 충돌
Windows 방화벽 차단
Tailscale ACL 차단
```

### 11-3. 프린터가 0대로 표시

```powershell
Get-Service Spooler
Get-Printer
```

가능한 원인:

```text
프린터 드라이버 미설치
프린터가 다른 사용자 세션에만 연결됨
Print Spooler 중지
네트워크 프린터 연결 끊김
SYSTEM 계정에서 프린터가 보이지 않음
```

특히 사용자별로 설치된 프린터는 SYSTEM 계정으로 실행되는 에이전트에서 보이지 않을 수 있습니다.

이 경우 프린터를 컴퓨터 전체 기준으로 설치하거나 에이전트 실행 계정을 별도로 검토해야 합니다.

### 11-4. CPU 온도만 표시되지 않음

확인 항목:

```text
LibreHardwareMonitorLib.dll 존재
에이전트 DLL 경로
지원되는 센서 이름
권한 문제
보안 프로그램 차단
```

온도 수집 실패가 에이전트 전체 실패로 이어지지 않도록 `temperature_c = null` 처리가 유지되어야 합니다.

### 11-5. 외부 주소가 504 Gateway Timeout

Dell 서버에서 확인:

```bash
curl -fsS http://127.0.0.1:8897/health
sudo systemctl status i-print-dashboard --no-pager
```

Nginx Proxy Manager Docker에서 호스트 8897로 접근 가능한지 확인합니다.

기존 장애 원인:

```text
Docker NPM 네트워크에서 Dell 호스트 8897 방화벽 차단
```

기존 복구 기준:

```text
172.19.0.0/16 → 8897/tcp 허용
```

Docker 네트워크 대역은 환경에 따라 달라질 수 있으므로 실제 NPM 네트워크를 먼저 확인합니다.

## 14. 다음 개선 권장 사항

현재 방식은 장비 두 대를 직접 코드에 등록한 1차 운영 구조입니다.

컴퓨터가 여러 대로 늘어나기 전에 아래 개선을 우선 진행하는 것이 좋습니다.

1. `devices` SQLite 테이블 생성
2. 관리자 화면에서 장비 추가·수정·비활성화
3. Tailscale IP와 표시 이름을 DB에서 관리
4. 신규 에이전트 자동 등록 토큰 방식
5. 에이전트별 고유 ID 발급
6. 8898 읽기 API 인증 추가
7. Tailscale ACL로 Dell 서버만 8898 접근 허용
8. 범용 `install-iprint.ps1` 제작
9. 에이전트 버전 표시와 원격 업데이트
10. 장비 상태 Heartbeat 저장
11. 프린터별 상세 상태 분리
12. 인쇄 문서·사용자·페이지 수 실시간 수집

현재 에이전트의 `/status`는 인증 없이 열리는 구조이므로 인터넷에 직접 공개해서는 안 됩니다.

Tailscale 내부에서만 사용하고, 장비 수가 늘어나기 전에 API 인증 또는 서버로의 Push 방식으로 강화하는 것이 안전합니다.
